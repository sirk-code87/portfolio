# 0005: Lesson memory with a capped digest per persona

## Context

I was giving agents the same corrections again and again, because a correction lived only in the session where I made it. Claude Code offers built-in agent memory, which lets an agent write its own notes.

## Decision

I built lesson memory as records with a promotion path.

- When I correct an agent, the session log spots the correction and asks me to confirm before writing a lesson note (or adding a hit to an existing one). Each note carries a trigger, a persona and a hit count.
- A build script compiles active lessons into a digest per persona, capped at 30 lines. Digests are generated by the script and never edited by hand.
- Persona skills load their digest at session start; the handoff runner includes it in every delegate's prompt.
- A weekly retrospective lists promotion candidates (three or more hits, cross-persona, or general). Promotion moves the lesson into a skill, an agent or `CLAUDE.md` (the instruction file read at the start of every session), and marks it promoted.

## Alternatives rejected

- **Built-in agent memory.** No evidence gate, no audit trail, and it stores whatever the agent believes, including unverified facts.
- **Appending corrections straight to `CLAUDE.md`.** That file is loaded everywhere; it would have grown without limit.

## Consequences

- 114 lessons in about five weeks: 45 promoted, 4 retired, 65 active.
- Persona scoping mostly failed. 102 of the 114 lessons were tagged general, 8 product and 4 finance, and the first week's lessons reached no persona digest at all. Most corrections happened in sessions with no persona in use. In practice the memory worked as an intake for `CLAUDE.md` and skill edits through promotion.
- 100 lessons had a single hit, so the promotion threshold rarely fired on recurrence alone.
- A digest overflowed its cap, which forced promotion or retirement as intended and also showed the scope key was wrong.
